## ADDED Requirements

### Requirement: Proxy shared playback policy

The system SHALL represent `proxy` and `shared` as explicit playback policy fields on web-originated provider video items.

#### Scenario: Proxy true policy

- **WHEN** the host selects a Bilibili item with `proxy=true`
- **THEN** the server returns a SyncRoom-controlled MPD/m3u8 URL and proxy segment URLs for playback

#### Scenario: Shared direct policy

- **WHEN** the host selects `proxy=false` and `shared=true`
- **THEN** the server may return Bilibili direct playback URLs to members without exposing provider credentials

#### Scenario: Shared false policy

- **WHEN** the host selects `shared=false`
- **THEN** the server uses anonymous or no-cookie parsing and member playback may fail for member-only content with a clear error

### Requirement: Proxied manifest generation

For `proxy=true`, the server SHALL generate or rewrite MPD/m3u8 manifests so media resources point to SyncRoom proxy endpoints while preserving quality, audio track, subtitle where available, and optional HEVC source metadata.

#### Scenario: MPD rewrite

- **WHEN** Bilibili returns a DASH MPD or equivalent media description
- **THEN** the server rewrites media resource references to SyncRoom proxy URLs and returns an MPD URL playable by Shaka

#### Scenario: m3u8 rewrite

- **WHEN** Bilibili returns a live or HLS m3u8
- **THEN** the server rewrites playlist resource references to SyncRoom proxy URLs and returns an m3u8 URL playable by Shaka

### Requirement: Segment proxy access

The playback proxy SHALL serve only media resources produced by a provider parse/proxy session and identified by opaque server-issued ids or tokens, not arbitrary client-supplied URLs.

#### Scenario: Known segment request

- **WHEN** Shaka requests a segment URL generated by SyncRoom
- **THEN** the proxy resolves the cached provider resource and streams the segment response

#### Scenario: Arbitrary URL rejected

- **WHEN** a client attempts to proxy an arbitrary URL not produced by an adapter parse
- **THEN** the server rejects the request without fetching the URL

### Requirement: Proxy SSRF protection

The playback proxy SHALL validate protocol, host, DNS/IP resolution, and private/reserved IP ranges before fetching upstream media resources.

#### Scenario: Private IP blocked

- **WHEN** a cached resource resolves to localhost, private network, link-local, or otherwise disallowed IP space
- **THEN** the proxy rejects the fetch and records a safe error without exposing sensitive data

#### Scenario: Unsupported protocol blocked

- **WHEN** a resource uses a protocol other than allowed HTTP or HTTPS media protocols
- **THEN** the proxy rejects it before any upstream request

### Requirement: Header and Range support

The playback proxy SHALL forward browser-compatible media requests with necessary provider headers such as Bilibili Referer and User-Agent, and SHALL support Range requests required by Shaka playback.

#### Scenario: Range request

- **WHEN** Shaka requests a byte range for a media segment
- **THEN** the proxy forwards the Range request upstream and returns a compatible partial response when upstream supports it

#### Scenario: Provider headers

- **WHEN** the proxy requests Bilibili CDN or media resources
- **THEN** it includes required Referer/User-Agent headers without exposing host credentials to the client

### Requirement: Proxy cache TTL

The playback proxy SHALL cache manifest and real segment resource mappings only for bounded TTLs and MUST NOT retain them indefinitely.

#### Scenario: Expired resource mapping

- **WHEN** a segment mapping TTL expires
- **THEN** subsequent requests for that mapping fail with a clear expired-resource response and do not fetch stale URLs

#### Scenario: Room cleanup

- **WHEN** a room is destroyed or provider auth is cleared
- **THEN** proxy mappings associated with that room are removed or become unusable

### Requirement: Direct-link fallback handling

For `proxy=false + shared=true`, the web room SHALL display direct-link playback success/failure and provide a clear path to retry or switch to proxy when direct playback fails.

#### Scenario: Direct playback fails

- **WHEN** direct-link playback fails because of CORS, expired URL, IP binding, Referer, network, or decode failure
- **THEN** the web room shows a clear error stage and offers proxy fallback instead of silently hiding the failure

### Requirement: Credential leak prevention

The playback proxy SHALL NOT include room host cookies, auth headers, raw upstream signed URLs, or sensitive provider headers in client-visible payloads, logs, or Admin views.

#### Scenario: Proxy error response

- **WHEN** an upstream media request fails
- **THEN** the error response omits provider credentials and sensitive upstream request headers

#### Scenario: Proxy log event

- **WHEN** the proxy records an upstream fetch or rewrite failure
- **THEN** structured logs include safe resource ids and failure stages but no raw credentials
